# NEON Admin Dashboard

لوحة الإدارة متاحة على المسار:

`/admin`

## منح صلاحية الإدارة

تسجيل الدخول وحده لا يمنح صلاحية الإدارة. يجب تفعيل أحد الخيارات التالية في بيئة الخادم:

### 1. البريد الإلكتروني

أضف متغير البيئة:

`NEON_ADMIN_EMAILS`

ويمكن وضع أكثر من بريد مفصولًا بفاصلة:

`admin1@example.com,admin2@example.com`

### 2. Firebase UID

أضف متغير البيئة:

`NEON_ADMIN_UIDS`

ويمكن وضع أكثر من UID مفصولًا بفاصلة.

### 3. Firebase Custom Claims

يمكن اعتماد المستخدم إذا احتوى Firebase ID Token على:

`admin: true`

أو:

`role: "admin"`

## نموذج إدارة المحتوى

- ملفات بنك الأسئلة المولدة تظل المصدر الأساسي ولا يتم تعديلها من لوحة الإدارة.
- أي تصحيح أو إخفاء أو اعتماد يُحفظ في PostgreSQL داخل `neon_question_overrides`.
- الخادم يطبق الـOverrides عند تقديم ملفات `/data/exams/*.json` للطلاب.
- عند تغير أي Override يتغير `adminRevision` في manifest، وبالتالي يتغير مفتاح Cache في مركز الاختبارات.
- السؤال بحالة `hidden` لا يصل إلى بنك الطالب الفعال.
- إعادة الضبط تحذف الـOverride وتعيد النسخة الأصلية.

## البلاغات

تستخدم اللوحة جدول `neon_question_reports` الموجود في نظام بلاغات الطلاب، وتضيف حقول المعالجة الإدارية عند الحاجة.

الحالات:

- `new`
- `reviewing`
- `resolved`
- `dismissed`

## سجل التدقيق

كل تعديل سؤال أو إعادة ضبط أو تغيير حالة بلاغ يسجل داخل `neon_admin_audit` مع:

- UID للمسؤول.
- البريد الإداري إن توفر.
- نوع الإجراء.
- الكيان المتأثر.
- الحالة قبل الإجراء وبعده.
- وقت الإجراء.

## كشف المكرر المحتمل

الفحص في لوحة الإدارة مخصص للمراجعة البشرية ولا يحذف الأسئلة تلقائيًا. تتم المقارنة داخل المادة الواحدة مع مراعاة تشابه النص وتوقيع الأرقام لتقليل النتائج الخاطئة.
