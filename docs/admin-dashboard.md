# NEON Admin Dashboard

لوحة الإدارة متاحة على المسار `/admin`.

## Bootstrap Admin

تسجيل الدخول وحده لا يمنح صلاحية الإدارة. لتعيين المسؤول الأساسي استخدم أحد الخيارات التالية في بيئة الخادم:

- `NEON_ADMIN_EMAILS`
- `NEON_ADMIN_UIDS`
- Firebase claim: `admin: true`
- Firebase claim: `role: "admin"`
- Firebase claim: `role: "super-admin"`

المسؤول الأساسي يعامل كـ `super-admin` وهو محمي من تغيير دوره أو إيقافه من داخل اللوحة لتفادي Lockout إداري.

## RBAC

بعد تفعيل مسؤول أساسي يمكن تفويض مسؤولين آخرين من تبويب **المستخدمون** داخل `/admin` دون إضافة كل مسؤول إلى متغيرات Railway.

### `super-admin`

جميع أقسام الإدارة، إدارة المحتوى والبلاغات والمستخدمين، تغيير الأدوار، وإيقاف أو إعادة تفعيل الوصول إلى المنصة.

### `content-admin`

إدارة بنك الأسئلة والبلاغات والمكرر المحتمل وسجل التدقيق، بدون إدارة المستخدمين أو منح الصلاحيات.

### `support`

عرض ملخص الإدارة والمستخدمين ونشاطهم، معالجة البلاغات وقراءة سجل التدقيق، بدون فتح أو تعديل بنك الأسئلة وبدون تغيير الأدوار أو إيقاف الحسابات.

### `student`

لا يملك صلاحية الدخول إلى لوحة الإدارة.

التحقق النهائي من كل Capability يتم على الخادم؛ إخفاء التبويبات والأزرار في الواجهة لتحسين تجربة المستخدم فقط.

## سجل المستخدمين

يستخدم النظام جدول `neon_platform_users` لحفظ Firebase UID، البريد والاسم عند توفرهما، الدور، حالة الوصول `active` أو `suspended`، سبب الإيقاف، أول ظهور، آخر نشاط، وآخر مسؤول عدّل الدور أو الحالة.

عند تشغيل لوحة المستخدمين يتم استيعاب المستخدمين المعروفين مسبقًا من `neon_users` وجداول الأهداف والاختبارات، وتعرض اللوحة عند توفر البيانات: الاسم والبريد وUID، الدور والحالة، آخر نشاط، عدد محاولات الاختبارات ومتوسطها، الهدف الدراسي، وآخر المحاولات.

## Platform-level Suspension

الإيقاف الحالي يمنع الوصول إلى خدمات NEON ولكنه لا يعطل حساب Firebase Authentication نفسه.

عند تحويل المستخدم إلى `suspended`:

1. `/api/access/session` يرفض الحساب.
2. `ensureAuth()` يمنع استكمال تحميل جلسة الطالب.
3. Access Guard المركزي يمنع الطلبات الموثقة إلى APIs المنصة حتى عند محاولة تجاوز الواجهة.
4. يسجل الإجراء في `neon_admin_audit`.

لا يستطيع المسؤول تعديل دوره أو إيقاف حسابه من نفس الجلسة، كما أن Bootstrap Admin محمي من التعديل داخل اللوحة.

تعطيل حساب Firebase نفسه يتطلب Firebase Admin SDK وصلاحيات خادم مخصصة، وليس جزءًا من هذه المرحلة.

- `users.read`

## إدارة المحتوى

ملفات بنك الأسئلة المولدة تبقى المصدر الأساسي. التصحيح أو الإخفاء أو الاعتماد يحفظ في PostgreSQL داخل `neon_question_overrides`، ويطبقه الخادم على `/data/exams/*.json`. تغير Override يغير `adminRevision` لإبطال Cache القديم، والسؤال `hidden` لا يصل إلى بنك الطالب. إعادة الضبط تحذف الـOverride وتعيد النسخة الأصلية.

## البلاغات والتدقيق

حالات البلاغات: `new`, `reviewing`, `resolved`, `dismissed`.

كل تعديل سؤال أو بلاغ أو دور/حالة مستخدم يسجل في `neon_admin_audit` مع المسؤول، الإجراء، الكيان، الحالة قبل وبعد، والوقت.

## المكرر المحتمل

الفحص للمراجعة البشرية فقط ولا يحذف الأسئلة تلقائيًا، مع مراعاة تشابه النص وتوقيع الأرقام داخل المادة الواحدة.
