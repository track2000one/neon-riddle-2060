# NEON Admin Dashboard

لوحة الإدارة متاحة على المسار:

`/admin`

## المسؤول الأساسي Bootstrap Admin

تسجيل الدخول وحده لا يمنح صلاحية الإدارة. لتعيين المسؤول الأساسي استخدم أحد الخيارات التالية في بيئة الخادم:

### البريد الإلكتروني

`NEON_ADMIN_EMAILS`

ويمكن وضع أكثر من بريد مفصولًا بفاصلة.

### Firebase UID

`NEON_ADMIN_UIDS`

ويمكن وضع أكثر من UID مفصولًا بفاصلة.

### Firebase Custom Claims

يدعم الخادم:

- `admin: true`
- `role: "admin"`
- `role: "super-admin"`

المسؤول الأساسي يعامل كـ `super-admin` حتى لو كان الدور المخزن في PostgreSQL مختلفًا، وهو محمي من تغيير دوره أو إيقافه من داخل اللوحة حتى لا يحدث Lockout إداري.

## الأدوار والصلاحيات RBAC

بعد تفعيل مسؤول أساسي، يمكن تفويض المسؤولين الآخرين من تبويب **المستخدمون** داخل `/admin` بدون إضافة كل مسؤول جديد إلى متغيرات Railway.

### `super-admin`

- جميع أقسام لوحة الإدارة.
- إدارة بنك الأسئلة.
- معالجة البلاغات.
- كشف المكرر المحتمل.
- قراءة سجل التدقيق.
- عرض المستخدمين.
- تغيير الأدوار.
- إيقاف أو إعادة تفعيل الوصول إلى المنصة.

### `content-admin`

- ملخص الإدارة.
- إدارة بنك الأسئلة.
- معالجة البلاغات المرتبطة بالمحتوى.
- كشف المكرر المحتمل.
- قراءة سجل التدقيق.
- لا يملك إدارة المستخدمين أو منح الصلاحيات.

### `support`

- ملخص الإدارة العام.
- عرض المستخدمين وتفاصيل نشاطهم.
- معالجة البلاغات.
- قراءة سجل التدقيق.
- لا يملك فتح أو تعديل بنك الأسئلة.
- لا يملك تغيير الأدوار أو إيقاف الحسابات.

### `student`

لا يملك صلاحية الدخول إلى لوحة الإدارة.

التحقق النهائي من كل Capability يتم على الخادم. إخفاء التبويبات أو الأزرار في الواجهة هو لتحسين تجربة المستخدم فقط وليس طبقة الحماية الأساسية.

## سجل المستخدمين

يستخدم النظام جدول:

`neon_platform_users`

ويحفظ بيانات تشغيلية مرتبطة بالمنصة، منها:

- Firebase UID.
- البريد والاسم عند توفرهما من جلسة Firebase.
- الدور.
- حالة الوصول `active` أو `suspended`.
- سبب الإيقاف الإداري.
- أول ظهور في المنصة.
- آخر نشاط معروف.
- آخر مسؤول عدل الدور أو الحالة.

عند تشغيل لوحة المستخدمين يتم أيضًا استيعاب المستخدمين المعروفين مسبقًا من جداول `neon_users` والتقدم والاختبارات حتى لا تبدأ اللوحة فارغة بعد نشر الميزة.

لوحة المستخدم تعرض عند توفر البيانات:

- الاسم والبريد وUID.
- الدور والحالة.
- آخر نشاط.
- عدد محاولات الاختبارات ومتوسطها.
- الهدف الدراسي والدرجة المستهدفة.
- آخر محاولات الاختبارات في صفحة التفاصيل.
- ملخص البلاغات إن كان جدول البلاغات متاحًا.

## إيقاف المستخدم

الإيقاف الحالي هو **Platform-level suspension** وليس تعطيلًا لحساب Firebase Authentication نفسه.

عند تحويل المستخدم إلى `suspended`:

1. `/api/access/session` يرفض الحساب.
2. `ensureAuth()` يمنع استكمال تحميل جلسة الطالب.
3. Access Guard المركزي يمنع الطلبات الموثقة إلى APIs المنصة حتى عند محاولة تجاوز الواجهة.
4. يتم تسجيل الإجراء في `neon_admin_audit`.

يوجد حاجزان ضد القفل الإداري غير المقصود:

- لا يستطيع المسؤول تعديل دوره أو إيقاف حسابه من نفس الجلسة.
- المسؤول الأساسي المعرف في متغيرات البيئة أو Firebase claim محمي من التعديل داخل اللوحة.

تعطيل المستخدم داخل Firebase Authentication نفسه يتطلب Firebase Admin SDK / صلاحيات خادم مخصصة، ولم يتم الادعاء بتوفيره ضمن هذه المرحلة.

## حماية الإدارة

التحقق من الصلاحيات يتم على الخادم، وليس بإخفاء الأزرار فقط. الواجهة تستخدم نفس Capability Matrix لتحسين تجربة المستخدم، بينما يبقى القرار النهائي للـAPI.

الصلاحيات الرئيسية:

- `dashboard.read`
- `content.read`
- `content.manage`
- `reports.manage`
- `duplicates.read`
- `audit.read`
- `users.read`
- `users.manage`

## نموذج إدارة المحتوى

- ملفات بنك الأسئلة المولدة تظل المصدر الأساسي ولا يتم تعديلها من لوحة الإدارة.
- أي تصحيح أو إخفاء أو اعتماد يُحفظ في PostgreSQL داخل `neon_question_overrides`.
- الخادم يطبق الـOverrides عند تقديم ملفات `/data/exams/*.json` للطلاب.
- عند تغير أي Override يتغير `adminRevision` في manifest، وبالتالي يتغير مفتاح Cache في مركز الاختبارات.
- السؤال بحالة `hidden` لا يصل إلى بنك الطالب الفعال.
- إعادة الضبط تحذف الـOverride وتعيد النسخة الأصلية.

## البلاغات

تستخدم اللوحة جدول `neon_question_reports` الموجود في نظام بلاغات الطلاب.

الحالات:

- `new`
- `reviewing`
- `resolved`
- `dismissed`

## سجل التدقيق

كل تعديل سؤال، أو إعادة ضبط، أو تغيير حالة بلاغ، أو تغيير دور/حالة مستخدم يسجل داخل `neon_admin_audit` مع:

- UID للمسؤول.
- البريد الإداري إن توفر.
- نوع الإجراء.
- الكيان المتأثر.
- الحالة قبل الإجراء وبعده.
- وقت الإجراء.

## كشف المكرر المحتمل

الفحص في لوحة الإدارة مخصص للمراجعة البشرية ولا يحذف الأسئلة تلقائيًا. تتم المقارنة داخل المادة الواحدة مع مراعاة تشابه النص وتوقيع الأرقام لتقليل النتائج الخاطئة.
