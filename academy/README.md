# MSAR NEON — NEON Academy

منصة تعليمية وتدريبية للقدرات والتحصيلي وSTEP، مع مسارات معرفة وألعاب وبرمجة ونظام تقدم متزامن.

## البنية المعتمدة حاليًا

الواجهة الأساسية هي تطبيق Vite متعدد الصفحات داخل `app/`، وتعمل صفحات `academy/` كطبقة Legacy انتقالية فقط إلى حين اكتمال نقل جميع المراكز.

المسارات العامة المعتمدة للمستخدم:

- `/` — بوابة مسار نيون والخطة الشخصية.
- `/exams` — مركز التحصيلي والقدرات.
- `/step` — مركز STEP.
- `/learning` — مكتبة المعرفة والدروس.
- `/games` — الألعاب والألغاز.
- `/kids-games` — ألعاب الأطفال.
- `/coding` — تعليم البرمجة عبر غلاف موحد أثناء نقل المركز من Legacy.
- `/trust` — مركز الجودة والثقة.

الروابط القديمة للمراكز يتم تحويلها تدريجيًا إلى المسارات المعتمدة، بينما تبقى ملفات Legacy الضرورية متاحة داخليًا للتوافق أثناء مرحلة الانتقال.

## بنك الأسئلة

يتم بناء بنك الاختبارات أثناء `npm run build` بواسطة:

`scripts/build-question-bank.mjs`

ويمر السؤال بالمراحل التالية:

1. التحقق من وجود السؤال والخيارات والإجابة الصحيحة.
2. توحيد النص العربي والأرقام لأغراض المقارنة.
3. إزالة التكرار المتطابق مركزيًا.
4. فحص Fuzzy Dedup مركزي محافظ للأسئلة شديدة التشابه، مع حماية المسائل التي تختلف أرقامها أو خياراتها.
5. اختيار النسخة الأعلى جودة عند وجود أكثر من نسخة.
6. حذف هوية المصدر وبيانات الصفحات من ملفات التشغيل النهائية.
7. إخراج ملفات JSON حسب المادة مع `manifest.json` موحد.

الحالة الحالية على فرع `performance-vite`: **2615 سؤالًا فريدًا في 6 مواد**، مع استمرار التوسع بعد المراجعة.

## حساب الطالب والتقدم

المصادقة تعتمد على Firebase Authentication. التقدم الأساسي وحالة الإتقان والنتائج تتم مزامنتها مع PostgreSQL عند توفر قاعدة البيانات.

يستخدم LocalStorage الآن كطبقة Cache/Offline ومصدر لترحيل البيانات القديمة، وليس كمصدر وحيد للحساب.

تشمل المزامنة:

- تقدم الدروس والأنشطة.
- محاولات الاختبارات.
- حالة إتقان الأسئلة.
- ملف الهدف الدراسي والخطة الشخصية.
- دفتر الأخطاء.
- حالة إنجاز خطة اليوم.

دفتر الأخطاء وخطة اليوم يستخدمان API الحساب `/api/student-state/*`، مع مزامنة بين الأجهزة وطابور محلي عند انقطاع الاتصال. الأسئلة التي تم إنهاء مراجعتها تسجل كحالة resolved في الخادم حتى لا يعيد جهاز قديم إظهارها.

## الخادم

`server-production.mjs` يقدم ملفات الإنتاج وواجهات API التالية:

- `/api/progress/*`
- `/api/mastery/*`
- `/api/success/*`
- `/api/student-state/*`
- `/api/competition/*`

وتوجد اختبارات GitHub Actions للبناء، مخرجات بنك الأسئلة، المسارات العامة، حماية واجهات الحساب، وتشغيل خادم Railway.

## مبدأ التطوير الحالي

الأولوية في مرحلة Stabilization هي:

1. إبقاء جميع المراكز خلف مسارات Canonical موحدة.
2. منع الأرقام الثابتة القديمة وربط مؤشرات المحتوى بالمصادر الفعلية.
3. تطبيق جودة وإزالة تكرار مركزية لبنك الأسئلة.
4. جعل بيانات التعلم المهمة متزامنة مع الحساب عبر الأجهزة.
5. نقل ما تبقى من Legacy تدريجيًا دون كسر تجربة الطالب الحالية.
